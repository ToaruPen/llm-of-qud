# M1 のゲーム側 mod

固定版 `2.0.211.56` の CTA で観測を送り、ハーネスからの判断を待つ mod。Modern UI、Harmony なしで動く。ゲーム側は `ws://127.0.0.1:4040` のクライアントであり、待機中や切断中に既定の行動は実行しない。

`LlmOfQud/` を隔離プロファイルの `Mods/LlmOfQud/` に置く。ゲームが認識する ID は `LlmOfQudM1`。C# は起動時にゲーム側の Roslyn がコンパイルする。通常のセーブへ直接導入せず、R0 の固定ビルド・mod・設定検査を通したプロファイルを使う。

## 起動と終了

2026-09-27以降は、ユーザーが同じMacで作業を続けられることを運用条件とする。並行作業中の実験には、R0ランチャーの **`--batchmode` を明示する**。Unityの表示・OS入力を使わないモードで、セーブ選択と初回armもゲーム内部から実行する。固定版での起動・操作・保存・正常終了・再起動を実測した。通常のウィンドウ起動、OSの入力送信、前面化、実ポインタ移動・フォーカス切替の試験は並行作業中に実行しない。Swiftホバー補助の以前の使用許可を、作業中の操作許可として扱わない。

背景起動の手順は次のとおり。

1. 隔離プロファイルと、そのプロファイルの有効mod構成に一致する既存セーブを用意する。ハーネスを新しいrunディレクトリで起動する。
2. ゲーム起動前に、プロファイル直下の `llm-start.json` へ `run_id`（新しいUUID）、`game_id`、`save_turn`、`save_sha256`（`Primary.sav.gz` のSHA-256）を書く。一時ファイルからrenameする。任意の `audit`・`development` はboolで、既定はfalse。残存する `llm-control.json` がある場合は起動を拒否する。
3. [R0ランチャー](../probes/R0-runtime/README.md)を `launch-background --batchmode` で実行する。起動指示は1回だけ消費し、Continueのゲーム内キュー、保存選択のUIコールバック、ロード直後のフックを順に使う。ID・ターン・ハッシュ・mod構成の不一致はエラー終了する。起動の期限は120秒。最初のキー入力は不要。
4. 通常のMCP操作を行う。背景起動の制御ファイルはLLMのツールに公開しない。
5. LLMと他の操作クライアントの呼び出しを止め、未完了の行動・モーダルがない判断待ちで、`llm-control.json` に `{"command":"save_and_quit","run_id":"現在のUUID","expect_seq":現在のseq}` を書く。古いrun/seqや実行中の要求は拒否する。ゾーンキャッシュを保存し、Primaryの更新を照合してから、`suspended` を送信して正常なWebSocket切断応答を待つ。その後、通常の非死亡終了を経てアプリを終了する。

終了通知の送信前にメニュー側がBridgeを破棄する競合を避けるため、保存後の通信待ちには上限6秒を設けている。応答なし・異常切断は正常終了と扱わず停止する。切断応答は通信の完了確認であり、台帳の永続化確認ではない。試験では保存ファイルとプロセス終了に加え、ハーネス台帳の `suspended` 行と `pending:null` を別途照合する。

セーブがない隔離プロファイルでは、保存IDの代わりに `"new_game":{"pregen":"Praetorian Prime","name":"Jev Hybrid Trial"}` を指定して新規開始できる。`run_id` は引き続き必須。標準のプリセット選択経路で能力値を初期化し、Roleplay・Joppaから開始する。ゲームID・保存ハッシュ・保存ターンとの混在は拒否する。期限は300秒。開始イベントで制御を登録し、最初の操作要求より前に出る通知も既存の通知規則で処理する。能力値を変えた治具やゲーム操作の決め打ちは使わない。

ランダムなMutated Humanの新規開始には `"new_game":{"random_genotype":"Mutated Human","name":"Jev Random Mutant"}` を使う。`pregen` とは排他である。遺伝型だけ固定し、ゲーム標準のRandomSelectionNoUIを職業・変異・能力値へ順に1回ずつ適用する。強さによる引き直しは行わず、Roleplay・Joppaから開始する。生成されたビルドコードと公開の初期構成を開始ログに残す。能動的な変異能力の操作や変異ポイントの割り振りは、現行の実行可能操作には含まれない。

背景起動でも `runInBackground` とゲーム内部のフォーカス旗を保持する。これらはOSの前面化とは別である。Unityの [batchmode仕様](https://docs.unity3d.com/6000.0/Documentation/Manual/PlayerCommandLineArguments.html) に基づく起動で、`-nographics` は指定していない。ゲーム窓がないため、このモードでのOBSゲーム窓録画は対象外。任意のキャラクタービルド指定、画面ロック・スリープ中の継続、未知の専用画面は受入範囲に含めない。

以下は人が操作する従来のウィンドウ起動手順であり、並行作業中には使わない。

1. [ハーネス](../harness/README.md)を新しい run ディレクトリで起動する。
2. 隔離プロファイルでゲームを起動し、セーブをロードする。mod 不一致の画面では現在の構成を保ってロードする。
3. プロファイル直下の `llm-control.json` に `{"command":"arm","run_id":"新しいUUID"}` を書く。部分読み取りを避けるため、一時ファイルを同じディレクトリに作って rename する。
4. 入力待ちなら、測定前の補助入力を1回行う。今回の実機試験では `KP_5` を使用した。EndPlayerTurn コールバックが arm を処理し、次の CTA からカウンタを測定する。初回 request が届くまでは MCP は `not_ready` を返す。
5. `get_state` → `act` → 必要なら `wait_for_turn` で操作する。`modal` があるときは `respond` で答える。測定中は人間のゲーム入力を混ぜない。

明示的に人へ制御を戻す場合は `{"command":"handoff"}` を同じ制御ファイルへ書く。I4 としてゲームログに記録し、ソケットを閉じて通常の入力へ戻す。このファイルはローカルの運用者向けであり、LLM のツールには公開しない。ハーネスを再起動するときは、古い走行を handoff し、新しい UUID で arm し直す。

従来のウィンドウ起動での開始前の画面操作と handoff 後の操作は測定外である。背景起動の新規開始経路とは区別して記録する。

## 操作と観測

| 操作 | 実装 |
|---|---|
| `move` | 8方向は `GameObject.Move`。上下は標準コマンドの階段・世界地図処理。Lost や遭遇による地上移動も結果に記録する。 |
| `attack` | `GameObject.AttackDirection`。8方向。 |
| `wait` | 固定版の `CmdWait` 本体に合わせた shim。火消し、解凍、探索と PassedTurn を含む。 |
| `explore` | AutoAct の `?`。世界地図、低 HP、可視敵がいる状態では開始を拒否。HP_CRITICAL、NEW_HOSTILE、ENGINE_STOP、STUCK、BUDGET で止める。budget は経過ゲームターンの上限（1〜40）。 |
| `goto` | 現在の地上・地下ゾーン内の既知セル `target:{x,y}` へ AutoAct の `M x,y` で移動する。到着、ゾーン変更、危険、予算で止める。世界地図は1マスずつ `move` を使う。 |
| `rest` | `until:healed`（既定）または `morning`。AutoAct の `r` / `z`。budget は1〜40ターン。低HPから休めるが、被害・新しい敵・エンジン停止・予算で止める。 |
| `get` | 自分のセルまたは隣接セルの可視の品に限り、`ground` の `pN` を指定する。Getの `InventoryAction.Process` で1品または1スタックを拾い、距離・可視性・同一ゾーン・取得可能性を実行直前にも検査する。 |
| `talk` | 8方向で隣接する可視NPCに話しかける。会話が終わるまで1判断を保持し、各ノードを `respond` で選ぶ。取引ボタンとTradeパーツを持つ会話選択肢は除外する。 |
| `eat` / `drink` / `apply` | 現在の `kit` に含まれる `item` IDを指定する。観測時に保持した実体がまだ所持・装備中で、該当する `InventoryAction` が1件だけある場合に `Process` を呼ぶ。Read・Trade・任意コマンドは受け付けない。 |
| `equip` | 現在の `kit` のうち未装備の所持品を指定する。手動装備の `DoEquip` / `CommandEquipObject` を一意に選び、ゲーム標準の部位選択・確認を `respond` で処理する。結果の `dispatched` は装備完了を保証せず、次の `kit.slot` を照合する。 |
| `open` | 現在の `kit` のうち未装備で所持中の、Containerを持つ非生物を指定する。標準の `Open` を一意に選び、中身の選択と続く操作メニューを `respond` で処理する。容器が閉じるまで行動は未完了。空の容器への収納は未対応なので、その確認にはNoまたは取消を選ぶ。 |
| `learn_skill` | `character.skill_catalog[].id` を `skill` に指定する。スキルは native Class、パワーは `親Class:Class` の安定ID。表示中の候補・未習得・SP・前提条件を実行直前に再確認し、標準の `SkillsAndPowersScreen.SelectNode` で確認と購入を処理する。 |
| `raise_attribute` | 6つの基本能力値の名前を `attribute` に指定する。APと基礎値上限を再確認し、標準の `StatusScreen.BuyStat` で確認と購入を処理する。 |

判断は run_id と seq で照合し、同じ seq は1回だけ受理する。行動の結果は次の CTA で確定し、結果と seq+1 の判断要求を送る。explore / goto / rest は複数ターンを委任し、停止後に結果を確定する。

`executed:false` は要求した効果の不成立を表す。拘束や混乱などで移動できなくても、時間・エネルギー消費や攻撃への転化が起こり得る。通常の `blocked` に加え、エネルギー減少または世界ターンの前進を検出した不成立には `blocked_after_effect` を返す。この検出がない場合も副作用全般がないことの証明にはしない。古い台帳は変更せず、その `turns_elapsed`・エネルギー・観測を読む。

観測は、自分の vitals、現在ゾーンで可視の対象、直近12件までのメッセージ、AfterRender の80×25地図。対象名には `GetDisplayName(AsIfKnown:false)`、状態には `Strings.WoundLevel` を使う。タイル表示では `BackupChar` を使う。内部カウンタと gameQueue の記録は台帳へ保存し、MCP の観測には公開しない。

`kit`（装備・所持品、最大64件）、`status`（表示される効果、最大32件、食料・水分の文言）、`place`（HUD の地名・世界地図・迷い状態）も送る。所持品 ID はその観測限り。[R9](../probes/R9-observation/README.md) の実機監査は 211 観測・208 前進ターンで合格した。

`ground` は自セル・隣接セルの可視かつ取得可能な品、`goals` はModern UIで読めるクエスト本文を送る。`goals` の非表示段・完了済みクエスト・折り畳まれた本文の除外と、16,384文字での省略表示は、実機治具6条件で確認した。追加したこの2欄は、従来のR9監査の対象には含まれない。詳細は [ハーネスの契約と実測](../harness/README.md)。

`character` はレベル・XP・次レベルのXP・未使用SP/AP、6つの基本能力値の現在値と基礎値、習得済みID、Modern UIのスキル一覧を送る。各候補には名前、親ID、費用、説明、公開前提条件、習得済み・現時点で購入可能かを含む。将来の育成計画のため、SP不足や前提未達の候補も含める。非公開で未習得のスキルは出さず、一覧は512件または250,000バイトで省略する。購入は確認画面で取り消せる。購入後の結果は次の観測で照合する。

ModalDriver は UI tick から画面を読み、`run_id / seq / token / answer_id` を照合して応答する。ゲーム行動の seq は消費しない。再接続用のモーダル履歴は 4,096 フレームまたは 16 MiB で上限となり、超過時は停止する。未知の画面が30秒続くと `modal_watchdog` を送る。
