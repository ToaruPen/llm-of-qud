# 状況別の移譲と自動移動の検証方針

現在は移譲ポリシーv3を使用する。[行動分類](jev-action-ownership.md)に従い、日常操作は低確率だけでは移譲せず、危険や判断を要する操作は高確率でも上位へ渡す。以下のv1/v2と試走結果は変更経緯であり、現在の一律閾値を意味しない。

2026-09-28。前回の30分試走では96.6%をClaude待ちに使い、確率不足の18回だけで約17.4分を使った。最後は正常な自動移動が6回続いた直後に確率0.47で移譲した。同じ目的地へ進み続ける処理と、状況が変わった際の判断を分ける。

## 今回の変更

Jevの選択確率は候補間の分布であり、安全確率ではない。確率値には手を加えず、移譲する閾値を状況別に変える。以下は較正済みの統計モデルではなく、今回の実地検証用の初期値である。

| 条件 | 基準0.5への加算 |
|---|---:|
| 敵・危険・HP不足がなく、既知の通常地形へ一歩進み、現在ゾーンの目標に近づく | −0.15 |
| 見えている敵がいる | ＋0.10 |
| 危険度2以上または未知の効果がある | ＋0.10 |
| HPが上位の回復閾値または60%を下回る | ＋0.10 |

複数の危険条件は加算する。閾値は0.35〜0.95の範囲に制限し、判定根拠を各decisionのroutingへ残す。安全な一歩の緩和はtravelモード、通常の地面表示、空いている移動先に限り、直近の失敗や反復停滞があれば適用しない。地形表示から全経路の安全を保証するものではない。

成長・装備機会、重大または未知の状態変化、計画切れ、ゾーン変化、反復失敗、戦術方針との矛盾は従来の上位判断を維持する。自動移動の中断・進捗なし・敵の出現、戦闘操作以外でのHP減少も上位へ戻す。新しい観測を上位が確認済みなら、同じ変化だけを理由に重ねて呼び出さない。

Claudeが新しい計画でautomatic_gotoを明示許可した場合は、現在の候補にあるgotoを決定的に実行する。現在ゾーンのtravel目標、十分なHP、未処理の成長機会なし、敵・重大な危険・未知の効果なしを毎回確認する。12ゲームターンの区切りごとに観測し、通常のBUDGET終了は継続できる。計画の最大24操作という期限は残す。旧計画には許可を補完しない。

この処理の実行者はログ上plan_executorとし、Jevの判断成功に数えない。通常の選択・迂回はJevが行う。上位モデルだけでなくJevの呼び出しも省ける一方、危険な変化を見落とさない停止処理が前提になる。

ゲーム側ではgotoを含むマクロを通常のHP減少でも停止させた。新しい公開された身体効果・発火・凍結も停止対象とし、通常の汚れや構えなどの小さな許可リストは除外する。未知の効果は停止する。見えない敵や隠れた効果を取得しない。停止時点の敵名・座標・新しい効果・時刻を診断ログへ保存し、描画後の観測との違いを確認できるようにする。ワイヤープロトコルは変更していない。

移動中の軽微な相談はtacticalとして呼び出す。現在の身体・装備・習得済みスキル・危険情報は保持し、スキル購入一覧は省略する。回答はgoal、guidance、target、horizon、selection、stop、automatic_gotoに限定し、memory・strategy・tacticsは元の計画から決定的に保持する。追加フィールドによる方針上書きは拒否する。成長・装備候補はこの相談には渡さない。限定相談はmedium、それ以外はhighのeffortを使い、キャッシュ・入出力・時間を区分して測る。モデルや認証方法は変更しない。

停止回数と、NEW_HOSTILE停止の直後に敵が見えなかった回数は機械集計する。後者は誤検出の確定ではない。前回はClaudeの記憶文で実数2回が3回に増えていたため、集計値を物語的な記憶より優先する。

## 事前検証と未解決点

保存済み18局面に閾値計算を適用すると移譲18→11件。削減対象7件のうち5件は当時のClaudeと同じ操作、2件は異なる。これはオフラインでの方針比較であり、未実行の操作の正解率や安全性を証明しない。最後の確率0.47のgotoは閾値だけでは移譲のままだが、新たな上位許可があれば自動継続の条件を満たす。

Python 303件、C#ポリシー125項目、モーダル134項目に合格。固定ゲームDLLに対するコンパイルも成功。Python・Swiftの対象静的検査は通過。C#の既存警告6件（旧API2件、コールバックを含む制御フロー4件）はRETAINとし、今回の変更では削除・抑制しない。

前回の前面化1回は原因未確定。監視にUNIX時刻を加え、起動・保存との時間関係を比較する。監視プロセスの終了コードを受入結果に反映し、非前面化に失敗した場合も先にゲーム保存と証拠保全を完了する。

今回の実地試走は前回の最新セーブ（turn872、HP36/36、地下1階、死体回収済み・帰還未達）から30分。隔離プロファイルとbatchmodeを使い、途中の操作はモデルと計画実行器に任せる。帰還・報告の確認、操作あたりの進捗、被害、反復失敗、上位待ち時間、入出力トークン、キャッシュを確認する。局面が変わるため前回との単純比較を因果効果とは扱わない。

## 前半の観測による修正

前半852.107秒で帰還クエストの完了を確認した。一方、到着後に一歩離れると旧目的地へ自動で戻る往復が発生したため、操作待ちのseq55でプレイヤーを意図的に中断し、turn1003で保存・終了した。台帳54操作、未処理なし、ゲーム終了0、前面化0を確認した。前半の監督プロセスは手動中断によるプレイヤー終了-2を検出して失敗扱いとしたが、保存と台帳検証は先に完了している。

到着を計画発行seqと対応させ、到着済みの移動許可は消費する。上位が後から明示的に再許可した場合は再訪できる。飲水30→29 dramsを新装備とする誤検出は、比較用の名前から液量だけを除いて防ぐ。液体の種類、装備の修飾値、説明などは保持する。同一会話内で同じ本文・選択の2往復を観測したら、Jevの確率に関係なく上位へ戻す。再相談後は新しい反復だけを数える。

限定相談ではgoalも更新できるようにした。初版では古いNPCや座標を含む直近の目標まで固定してしまっていたためで、長期ビルド方針は保持する。また再起動時に前回reportのplanを読み込む任意のresume-planを追加した。以前の許可を即実行せず、現在の観測による上位の再確認を必ず先に行う。旧形式の保存計画への互換性は維持する。

これらは再現テストで失敗を観測してから修正した。後半は最新セーブと計画から残り947.893秒を実行し、二つの試走のプレイヤー稼働時間を合計30分とする。修正・テスト・起動終了の時間はこの30分に含めない。

中盤653.852秒でArgyveへの最初のアーティファクト納品と75 XP増加を確認した。その後「If I must. [Accept Quest]」が表示されているのにJevがCancelを繰り返したため、seq26で再び保存した。選択確率0.94の誤った分岐もあり、確率だけで判断の妥当性を保証できない実例となった。会話履歴に選択済み項目しかなく、提示された未選択の項目が欠けていたことも確認した。

## ランダムMutated Human試走後の追加修正

回避方針の確認済み敵は名前と座標で保持し、視界から消えただけでは再相談しない。未確認の名前・座標、敵の移動、HP減少、ゾーン変化、計画期限では従来どおり戻す。視界外の敵を倒した、存在しない、と判断する変更ではない。

閾値ポリシーv2では、回避方針中の通常地形への一歩について、全可視敵との距離が縮まらず最短距離が増える場合、敵可視の加算0.1を相殺する。HP不足・危険・未知効果・失敗・停滞があれば相殺しない。接近や攻撃を緩和する変更ではなく、基準0.5は維持する。また安全な目標方向の一歩と限定相談をexploreにも適用する。自動gotoの許可は引き続きtravelに限る。

通常食料の取得は装備可能という理由だけでビルド再評価を起こさない。装備候補自体は上位へ提示し、実際に装備された物の変更は評価する。観測されたtorch (unburnt)とlit torch (blazing)を比較時だけ同一視するが、説明や性能値、装備部位、別の修飾は残す。前回の実ログ4観測をfixture化し、食料・点灯での誤検知と本当の性能変更の検知を検証した。

characterにはゲーム標準のキャラクター画面と同じ変異一覧・ランク・説明・欠点、遺伝型・職業・MPを追加する。旧観測は受理し、新フィールド群は全体で追加する。書き手はCharacterGrowth.Buildのみ。変異の取得・成長はビルド確認の対象となり、確認後はJevにも現在の情報が渡る。能動変異の発動、MP消費、射撃の実行機能はまだない。
