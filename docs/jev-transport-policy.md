# Claude/Jev の待機制限と入力共有

2026-09-28 の改善。対象は Python のモデル通信・入力整形・判断期限で、ゲーム側プロトコルは変更しない。

Claude CLI は `--safe-mode`、ツールなし、独立した置換システムプロンプト、購読 OAuth のまま使う。`stream-json --verbose --include-partial-messages` で通信の進行を観測し、最終結果の構造と候補 ID を検証してから操作する。途中の応答は操作に使わない。

| 制限 | 設定 |
|---|---|
| Claude 呼び出し全体 | 既定で独自の上限なし |
| 完全な JSON イベントが届かない時間 | 既定で独自の上限なし |
| CLI の `API_TIMEOUT_MS` | 独自の上書きなし。CLI標準／既存環境に従う |
| `CLAUDE_CODE_MAX_RETRIES` | 1 |
| 無限再試行の watchdog | 無効 |
| 構造化出力の修正上限 | 2 |
| 標準出力・標準エラー | 各4 MiB |
| 実プレイの終了時刻 | 判断待ちにも適用。期限後の新規操作を禁止 |
| 既に受理された操作のダイアログ | 終了時刻から120秒の後処理枠 |

再試行は CLI 内の API 通信に限る。ゲーム操作や失敗した CLI 呼び出し全体を自動再送しない。実行直前には従来どおり観測の一致を確認する。終了・失敗・キャンセル時は、その呼び出しで作ったプロセスグループを終了させる。

OBS試走後の指示により、推論全体300秒・無応答270秒・独自API待機120秒の設定を撤廃した。指定された試走時間と手動中止は別の終了条件として維持する。CLIやサーバー内部の通信期限まで無期限になるという意味ではない。`run_cli` の明示的な期限引数は検証・呼び出し元の指定用に残し、既定値を `None` にする。

保存する診断情報は、開始時刻、最初と最後のイベント時刻、イベント種別ごとの件数、出力バイト数、取得できた使用量、期限の種類、終了コードなど。生の思考、イベント本文、標準エラー本文は保存しない。`first_event_s` は CLI 初期化を含み、API 応答開始時刻とは限らない。`partial_usage` は途中経過であり、各行を合算して課金・キャッシュ使用量として扱わない。最終 `usage` が取得できた成功呼び出しを集計の基本にする。

キャッシュ対象の固定定義は引き続きシステムプロンプトへ分離する。動的入力は、完全に同一の値を `definitions` と `$ref` で共有する。情報の要約や切り捨てではなく、元の入力に厳密に復元できる符号化である。既存データに参照と紛らわしい構造がある場合、または短縮できない場合は `inline-v1` でそのまま送る。バイト数の削減と、モデルのトークン数・判断品質・応答時間の改善は別々に検証する。

`hostile_response=avoid` を上位判断の選択肢に追加した。Claude が現在の敵を評価して迂回を選んだ場合に、Jevへ経路と目標を渡せる。敵の公開名・座標・数、ゾーン、計画時のHPを比較し、状況が変われば上位へ戻す。危険な状態変化、計画期限、成長・装備の評価は従来どおり別に判定する。`replan` の既存の意味は変えない。Jevが回避中に攻撃を選んだ場合も上位へ戻す。
