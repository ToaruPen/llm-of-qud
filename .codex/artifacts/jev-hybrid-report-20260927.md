## 実装と境界

- `harness/hybrid_policy.py`：候補生成、確率検証、公開観測からの入力構成、短期履歴、停滞検出。
- `harness/hybrid_models.py`：Jev API、公式Claude CLIの隔離呼び出し、有限の時間・回数制限。Claudeは計画を返すだけでゲームツールを持たない。モデル指定は省略し、実際の応答のモデルIDを記録。
- `harness/hybrid.py`：モデル選択から既存MCPへの実行、run/seq/観測/モーダルトークンの照合、受理済み操作の結果待ち。
- `mod/LlmOfQud/Observation.cs` と `harness/wire.py`：追加の `item_details`。過去の観測・台帳の読み取りは維持。
- `BackgroundSession.cs` / `BackgroundPolicy.cs` / `Runtime.cs`：プリセットを標準のキャラクター作成経路から選択して新規開始。開始通知の処理も含め、OS入力なしで最初の判断待ちへ進む。

射撃、発動能力、取引、容器内の品の出し入れは既存実行APIの対象外で、モデルにも明示した。すべての未知の情報や判断ミスを自動検出する仕組みではない。

## 初回試走で判明した問題

`run6` は663.3秒、32行動・14会話回答で正常保存・終了したが、クエストは取得できなかった。Jevは依頼説明の途中で取消を0.57、0.80、0.85の確率で選んだ。高確率でも誤判断は起こる。

この3観測を固定して、会話履歴・継続／取消の効果を補った入力で再評価すると、説明を続ける選択が0.93、0.83、0.79になった。3件の再評価であり、一般的な正解率や変更ごとの因果効果は主張しない。証拠は `.runtime/jev-hybrid-20260927/conversation-replay/`。

同時に、新規開始のsilentなビルド読み込みでは割り振り済み能力値が反映されず、HP9/9になる問題を発見した。標準の `SelectPregen` を通すよう修正。`run7` はPraetorian Prime、Roleplay、Joppa、新規世界から開始し、HP21/21、Strength22／Agility18／Toughness21などの初期値をログで確認した。両runは同条件の比較実験ではない。

初回版では過去の所持品を履歴ごとに重複して渡していた。修正版は状態変化を保持し、変化しない所持品・クエスト本文の重複を減らした。Claudeの成功応答の中央値は初回45.35秒、修正版24.14秒だったが、別run・別入力なので差分圧縮の因果効果を測定した数値ではない。

## 停止と残る課題

8回目のClaude呼び出しは `plan_expired` による再計画で、120秒の期限まで結果が返らなかった。プロセスを終了し、停止を確認した。内部生成待ちと通信待ちのどちらが原因かは、今回保存した記録から切り分けられない。認証や隔離条件を変える再試行は行っていない。ask-claudeスキル（`~/.codex/skills/ask-claude/SKILL.md`）の次の指示にも従い、同じ失敗要求を再送せず終了した。

> Do not install, update, log in, create a setup token, inject credentials, switch providers, or retry automatically.

その時点では未完了操作がなく、運用側が保存・正常終了を実施した。タイムアウトを成功扱いにしたり、代わりの固定操作をゲームへ送ったりしていない。

残る評価対象は、戦闘・回復・死亡復帰、長期目標の維持、計画更新の頻度、上位モデルのタイムアウト時の運用、条件を揃えたClaude単独との比較である。現在の成果は、新規開始から実ゲームで動く階層プレイヤーと、成功・誤判断・停止まで追跡できる検証記録である。
