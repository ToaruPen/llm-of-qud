## 所見（合否ではない）

- **タイル表示で変わったのは地図の読み方だけ**である。`probe:map` の字形は `Char` ではなく `BackupChar` に入る。ほかのプローブの DETECT / ANSWER / RESULT は ASCII の走行と同じ文字列で同じ結果になった。
- **非フォーカスでの進行の条件。** 緩和策なし（`OptionMusicBackground=No`）では Update 自体が止まる（0 Hz）。`runInBackground=true`＋毎 tick の `XRLCore.bThreadFocus=true` で UI tick は回る（force）が、ゲームスレッドの PlayerTurn は `GameManager.focused` で待つ。`GameManager._focused=true` をフィールドへ直接書く（setter の `ClearInput` を通さない）と、PlayerTurn がコマンドを消費してターンが進んだ（play）。本番のブリッジはこの 3 点を周期的に再設定する。
- **`_focused` の書き直しの副作用。** 実際に再フォーカスしたとき、setter は false→true の遷移を見ないので `Keyboard.ClearInput()` が走らない。人が触らないエージェントでは問題にならないが、人が同じウィンドウを操作する運用（デバッグ）では、再フォーカス直後の残留入力に注意する。
- **`CmdWait` の欠落か遅延。** 1 標本で `dTurns=0` になり次で回復した。PlayerTurn 入口の `ClearMouseEvents(LeaveMovementEvents: true)`（`XRLCore.cs:734`）で落ちたのか、1 秒の境界で遅れただけかは区別していない。ブリッジは「積んだコマンドが消費されたか」を結果で確かめる設計にする（08 §3 の P' と消費確認）。
- **ワーカーの未検証事項のうち解消したもの。** macOS で別アプリをクリックすると `Application.isFocused` が偽になる（`appFocused=False` が 30 標本）。**残るもの。** (a) ASCII 描画でも照準の imposter が出る可能性（PickTarget は `UseImposters` だけを見て `UseTiles` を見ない）。実行プロファイルはタイルなので優先度は低い。(b) `AfterRenderImposter` の登録はセッションの間残る（Remove の API がない。`probe:map` と同じ）。(c) tick が毎フレーム `Application.isFocused` を読むのは全プローブに共通の変更（bool 1 個。無害）。
- **操作。** 全 wish を貼り付け（`pbcopy` → cmd+v）で入力し、余計な画面（AbilityManagerScreen 等）は一度も開かなかった。ウィンドウ表示（1456x819 のフレーム）で Continue、セーブ、導入ポップアップ、wish 欄の座標は全画面と同じだった。フォーカスを外す操作は背景のタイマー（`osascript` で Finder を前面に → 一定秒後にゲームの pid を前面に）で行った。
