## 所見

- 中心集合 M（yesno / askstring / pickoption / stale / asknumber:mouse / asknumber:kb / conv）は全件 PASS。README §10.1 の「Legacy へ全面後退させる失敗」は 1 件も出ていない。
- 実会話（talk）で、直接 `OnActivateCommand(menuData[k])` を呼ぶ応答が 3 ノード連続で正しいノード遷移を生んだ（C-F2-conversation-26 の実機確認）。
- getvk ピッカーへの `PushKey` / `PushMouseEvent("PointerOver")` は、P' を確かめる UI タスクの中で積めば消えなかった（C-F6-threads-hooks-12、C-F7-observation-11 の実機確認）。
- 操作上の問題（プローブの問題ではない）: 自動化ツールで wish 文字列を打つと、文字が TMP の入力欄に入ると同時に legacy の `Keyboard` キューにも Adventure 層のコマンドとして残り、wish が戻った後にゲームスレッドが消費する。「a」は `CmdAbilities` なので AbilityManagerScreen が開く。自動化ツールから送る Escape はゲームに届かない（物理キーは届く）。対策として、wish ハンドラの `finally` で `Keyboard.ClearInput()` を呼ぶ変更を入れた（走行 3 から）。
