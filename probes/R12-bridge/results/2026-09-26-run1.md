R2 の観測は固定したゲーム状態と合成 UTF-8 文字列で、要求サイズは約 3.2 KB。1,000 回の LLM 判断やゲーム操作の試験ではない。生ログを再計算し、seq の順序、件数、切断をまたぐ本文ハッシュの一致を別途確認した。

R1 はゲームスレッドの CTA 内で同期ブロックし、待機中に gameQueue を回さない。終了時は PassTurn を 1 回だけ呼ぶ。エネルギー消費は `GameObject.UseEnergy` の乱数補正（逆コンパイル `XRL.World/GameObject.cs:3670` 付近）があるため、固定の 1,000 差を合格条件にしない。呼出回数、エネルギーが 1,000 未満になったこと、次 CTA、EndPlayerTurn を照合する。

起動時の `GalaxyCSharpGlue` 不在例外は R5 走行 4b と同じ。プローブ中の例外とは分けて扱う。全ログに一切例外がない、という主張はしない。

`Player.log` は最初のセッション、`Player-unfocused.log` は AppleScript 切替で再試験したセッションの原本。`r2-server.jsonl` はサーバー側原本。各セッションの最初のプローブ開始から記録終了まで、意図的切断の捕捉済み例外を除き、新しい例外行は 0。両セッションを `verify_run.py` で再計算し、**R1 の全 4 条件と R2 が合格**した。最終結果は `full-summary.json`。初回時点の `partial-summary.json` も履歴として残した。

Python の再送検査は、不正 seq・重複・切断中の本文変更・不正 envelope のテストが未実装状態で失敗することを確認し、実装後に 3 テストが通った。ログ検証には再起動をまたぐ統合、不足条件、両セッションのプローブ中の例外、標本の空白期間のテストを加え、修正前の失敗と修正後の成功を確認した。計 8 テストが成功。`verify_run.py` は 4 条件が揃わなければ失敗し、実測でも最後の 600 秒試験の終了前は不合格、終了後は合格した。

独立確認で、標本数だけでは停止後のまとめ採りを見逃す余地が見つかったため、最初・最後を含む各標本間隔が 2 秒未満であることを検証に追加した。今回の有効な 4 走行はこれも満たす。フォーカスの証拠は約 1 秒ごとの標本であり、標本間の一時的な切替を連続監視したものではない。

後続の接続先はユーザー指定により Claude Code / Opus 5.5 / xhigh。公式 ID `claude-opus-5-5` で最小呼び出しが成功し、返却モデル名が一致した。ゲームとの MCP 接続、最初の自律ターン、R0 全体、R3 / R4 / R9 は未実施。

操作上の注意: UI ツールの Ctrl+W は修飾キーが届かず、wish の起動に使えなかった。実験専用の `r12-command.txt` を EndPlayerTurn で読む入口を追加して起動した。主メニュー → セーブ選択 → mod 差分で現在の構成を維持 → ロードは UI 操作で確認できたが、新規キャラクター作成の無人完走は試していない。

非フォーカス試験の初回は、UI ツールの Finder 選択・Raise・クリック・アプリ切替キーでは `Application.isFocused` が false にならなかった。60 秒のうち判定対象の 57 標本が不一致で、合格には数えない。元の試行は `Player.log` に残した。ユーザーが AppleScript の使用を許可した後、再起動して同じセーブをロードし、CTA 開始直後に Finder を前面にして再試験した。再試験は 60 秒・600 秒とも全標本で実フォーカス false。OS の切替記録は `focus-control.jsonl`、ゲーム側は別の `Player-unfocused.log` に保存した。
